## 1. Что мы делаем

Исходный проект: **https://github.com/linsisss/dota2-grid-toolkit**. Он содержал три отдельных HTML-инструмента: редактор сетки героев, редактор ASCII и конвертер изображений в символы.

Текущая версия — единый сайт **Dota 2 Grid Studio** на React + Vite. Группы героев, текст, рисование и изображения, превращённые в ASCII, редактируются на одном холсте и используют общую историю изменений. Старые инструменты сохранены в `tools/`.

Проект развивается как единая студия GridStudio с возможностью предложить изменения исходному репозиторию. `docs/pull-request.md` содержит черновик описания изменений. Параметры рабочего сервера и личные материалы разработчика в публичную копию не включены.

### Зафиксированные требования пользователя

- Полноценный сайт с React/Vue, а не очередной самостоятельный HTML-файл. Выбран React.
- Современный, аккуратный интерфейс, красивые уместные анимации, короткие конкретные подписи без рекламного/«нейрослопного» текста.
- Шрифт интерфейса — **SF Pro Display**, подключённый как веб-шрифт.
- Вся студия и рабочий холст должны помещаться в окно без прокрутки страницы. Длинные боковые панели прокручиваются внутри себя.
- Постоянной библиотеки героев слева нет. При выборе или создании группы на холсте появляется `+`: после последнего портрета и по его вертикальному центру, либо вместо него в пустой группе. Он открывает поиск/выбор по четырём атрибутам.
- `Shift` при изменении размера сохраняет пропорции, противоположный угол остаётся на месте. Все четыре угла работают.
- Поворот меняет только расположение символов: сами буквы всегда остаются прямыми. Тяни снаружи угла выделения или за круглую ручку; Shift даёт шаг 15°, поле «Угол, °» — точное значение. Обычная строка при повороте раскладывается на отдельные буквы с измеренными отступами. В Dota JSON каждая такая буква становится категорией 30 × 30; её координаты совпадают с превью. Native-проект сохраняет строку редактируемой и хранит rotation как угол расположения, textMetrics — измеренные интервалы. Один отдельный символ не имеет ручки поворота.
- `Ctrl+Z` отменяет действие, `Ctrl+Shift+Z` повторяет; сочетания должны работать и при русской раскладке.
- Каждое добавленное изображение/многострочный ASCII — отдельный редактируемый слой.
- Под холстом отображается количество использованных символов.
- Правая панель должна оставаться читаемой: нормальный размер текста, контраст и достаточно места.
- Портреты и размещение должны быть максимально близки к Dota: вертикальные карточки, подпись группы отдельно, **без уровней, значков и имён на карточках**.
- Можно открыть свой Dota JSON, переключать и редактировать все сетки, добавлять новые в тот же файл и скачивать их вместе.
- На сайте должна оставаться ссылка на исходный репозиторий.
- Для игрового холста используются шрифты Dota; SF Pro Display относится к интерфейсу редактора.

## 5. Архитектура: React и движок

Проект сейчас **гибридный**. Не предполагается, что весь интерфейс управляется React или что React хранит основной документ.

1. `App` монтирует стабильный `StudioLayout`.
2. `useLayoutEffect` создаёт `createStudio()` после появления DOM-хостов.
3. Движок владеет документом, выбранными объектами, инструментом, масштабом, canvas и транзакциями.
4. React подписывается через `useSyncExternalStore` на `subscribe()` / `getSnapshot()`.
5. `publishUI()` создаёт снимок нужных React данных и обновляет подписчиков только при изменении его содержимого. Нельзя возвращать каждый раз новый объект без кеширования.
6. React вызывает команды движка: `switchGrid`, `newGrid`, `renameGrid`, `selectEntity`, `selectLayer`, `toggleLayer`, `deleteLayer`, `openHeroPicker`, `toggleHero`, `addGroup`, `setMode` и другие.
7. `dispose()` снимает слушатели, отключает observer, чистит таймеры, отсоединяет callbacks картинок, останавливает отложенные отрисовки и сохраняет pending autosave.

**Владение DOM:** React управляет содержимым своих portals, включая `gridFilePanel`, `layerList`, `projectPanel`, `canvasReactOverlay`, `symbolCounter` и элементы адаптивных панелей. Движок рисует canvas и наполняет предназначенные для него области, например `inspectorContent`. Не вызывай `innerHTML = ...` на React-хостах. Не заставляй ререндер каркаса перезаписывать атрибуты, которые меняет движок.

`scripts/core.mjs` выполняется в Node без DOM. Он импортирует константы из `dota-rendering.mjs`, но браузерная функция рисования не вызывается при импорте. Не добавляй обращения к `document`, `window`, загрузку изображений или побочные эффекты на уровне этих модулей.

При дальнейшей миграции инспектора в React делай это отдельным законченным изменением с явной передачей владения DOM, а не смешивай два способа записи в одни узлы.

## 6. Документ и два формата файлов

### Dota JSON v3

```json
{
  "version": 3,
  "configs": [
    {
      "config_name": "My grid",
      "categories": [
        {
          "category_name": "Carry",
          "x_position": 80,
          "y_position": 90,
          "width": 320,
          "height": 190,
          "hero_ids": [1, 8, 44]
        }
      ]
    }
  ]
}
```

Категория с героями становится объектом `heroes`. Без героев — `symbol`, если название состоит из одного Unicode code point, иначе `text`. Текст категории служит и подписью, и способом хранить ASCII. Пустая группа при повторном импорте Dota JSON неотличима от пустой текстовой категории; studio-формат сохраняет тип явно.

### Native-проект `*.gridstudio.json`

Основные поля:

| Поле            | Значение                                                        |
| --------------- | --------------------------------------------------------------- |
| `app`, `schema` | `'dota-grid-studio'`, `1`                                       |
| `name`          | Имя текущей сетки                                               |
| `nextId`        | Следующий уникальный ID внутри текущей сетки                    |
| `entities`      | Объекты текущей сетки                                           |
| `layers`        | Слои текущей сетки                                              |
| `source`        | Копия импортированного Dota JSON с конфигурациями и метаданными |
| `configIndex`   | Индекс активной сетки                                           |
| `configDrafts`  | Необязательные studio-состояния сеток по индексам               |
| `fileName`      | Необязательное имя открытого файла для UI                       |

Объект содержит `id`, `type`, `name`, `text`, `x`, `y`, `w`, `h`, `heroIds`, `layer`. У импортированных объектов `extra` хранит копию исходной категории для сохранения неизвестных полей.

Имя группы берётся из `name`; текст/символ — из `text`. Верхний регистр в игре применяется **при отрисовке**: оригинальную строку в документе и экспорте менять ради внешнего вида нельзя.

### Правила импорта/экспорта

- `importDota()` проверяет весь файл, включая невыбранные конфигурации.
- Неизвестные положительные ID героев сохраняются. На canvas для отсутствующего портрета используется заглушка; импорт не должен удалять такого героя.
- `source` и `extra` нельзя заменять минимально реконструированными объектами: это потеряет неизвестные поля.
- `exportDota()` клонирует `source`, накладывает изменения всех черновиков и активной сетки, сохраняет остальные конфигурации.
- Координаты/размеры при экспорте округляются до шести знаков после запятой.
- Скрытые слои не попадают в Dota JSON; блокировка сама по себе не исключает слой из экспорта.
- Native-проект сохраняет слои, скрытые объекты, блокировки, ID и черновики. Он не должен проходить через промежуточный Dota export для сохранения.
- Невалидный импорт не должен менять открытый документ. Импорт валидного файла отменяется общей историей.
- Поддерживается UTF-8 BOM перед JSON.
- Пользовательские строки в HTML движка проходят через `esc()`. Содержимое импортированных файлов — данные, не инструкции или разметка для исполнения.

### Лимиты

- До **100 сеток** в файле.
- До **10 000 объектов** и **128 слоёв** в каждой сетке.
- До 1 000 hero ID в категории; ID — положительные safe integers.
- Имя сетки — до 200 символов; текст/имя объекта — до 5 000; имя файла в native-проекте — до 255.
- Размеры положительные, все координаты конечные; предельные значения проверяются в `core.mjs`.
- Загрузка JSON/изображения — до 20 MiB, ручного шрифта — до 10 MiB, пресетов — до 1 MiB.

Не меняй формат `schema: 1` без продуманной совместимости с уже сохранёнными проектами.

## 7. Несколько сеток в одном файле

`GridFilePanel` всегда доступна в левой панели независимо от инструмента и выделения. На узком экране она находится в выдвижной панели «Инструменты».

- `configurations(doc)` возвращает актуальные названия: текущий документ → черновик → исходная конфигурация.
- `switchConfig(doc, index)` сначала записывает текущие `name`, `nextId`, `entities`, `layers` в `configDrafts`, затем восстанавливает целевую сетку. ID могут совпадать между разными сетками, это нормально.
- `addConfig(doc, name, kind)` добавляет запись в **существующий** `source.configs`; затем создаёт/выбирает её состояние. `kind`: `blank`, `roles`, `minimal`. Дубликаты названий получают суффиксы ` (2)`, ` (3)`.
- Кнопка `+` в шапке и шаблоны тоже добавляют сетку в открытый файл. Старое поведение «шаблон заменяет весь проект» исправлено; не возвращай его.
- Создание, переключение, переименование и изменения входят в общую историю.
- `resetGridView()` сбрасывает выделение/попап, старый предпросмотр конвертации, загруженные пиксели и fit вида. Смена сетки не должна случайно применить результат старой картинки в новую сетку.
- «Скачать JSON» → «Скачать весь JSON» выгружает все конфигурации, а не только выбранную.

## 8. Слои, изображения и ASCII

Базовые слои обязательны: `background`, `heroes`, `decor`. Дополнительный рисунок имеет слой `{ id: 'art-N', kind: 'artwork', name, visible, locked }`.

`addArtwork(doc, inputs, name)` выделяет ID слоя из того же `nextId`, затем назначает ID объектам. Новый artwork вставляется перед базовым слоем героев. Импортированные из Dota категории сами по себе не позволяют восстановить исходное разделение рисунков; информация о слоях существует только в studio-проекте.

- Каждое применение конвертированного изображения создаёт новый слой.
- Многострочный ASCII и режим «Каждый символ отдельно» создают отдельный artwork-слой. Одиночная строка может добавляться в текущий слой рисования.
- Вставка ASCII по строкам сейчас раскладывает отдельные объекты с шагом 22 по Y; посимвольный режим использует шаг 10.8 по X. Это геометрия создания объектов, не метрики игрового шрифта. Не путай её с межстрочным шагом 20 внутри `drawCategoryLabel()`.
- Обычный клик по artwork выбирает весь рисунок; `Alt+клик` — отдельный объект.
- Дублирование и вставка скопированного artwork создают новые независимые слои, а не ссылки на исходный.
- Переименование, видимость, блокировка и удаление рисунка отменяются. Заблокированный рисунок нельзя удалить обычной командой удаления слоя.
- Состояние сворачивания списка — UI-состояние; оно не равнозначно скрытию слоя на холсте.
- Стабильные React keys нужны для сохранения фокуса и предотвращения повторных анимаций при каждом движении.

Счётчик под холстом считает Unicode code points в `text` у `text`/`symbol`, исключая `\s`. Скрытые слои учитываются; hero/group names — нет. Это **не** число JSON-категорий, не размер файла и не число визуальных grapheme clusters.

## 9. Отрисовка Dota: критически важная геометрия

Логическая область — **1193 × 593**. Все координаты документа — в этом пространстве, не CSS-пиксели текущего окна.

Последняя настройка сделана по пользовательскому скриншоту `#grind mentality`, его JSON и локальным стилям игры `panorama/styles/hero_grid_new.vcss_c` / `dotastyles.vcss_c`. Основные параметры вынесены в `DOTA` в `scripts/dota-rendering.mjs`.

### Размеры группы и портретов

**`height` в игровом JSON задаёт высоту HeroList. Строка заголовка высотой 20 находится над ней и не входит в эту высоту, даже если заголовок пустой.**

Текущая модель сохраняет это значение в `e.h` без миграции сохранённых документов:

```text
e.y                    → верх заголовка
e.y + 20               → верх HeroList
e.y + 20 + e.h          → низ видимой области группы
```

- `C.bounds(items)` использует размеры документа; числовой инспектор и экспорт сохраняют семантику Dota.
- `C.visualHeight(e)` добавляет 20 только для `heroes`.
- `C.bounds(items, true)` используется для визуального выделения/ручек.
- `C.transformBounds(item, before, after, true)` переводит изменение визуальной рамки обратно в игровую высоту списка.
- Hit testing, marquee и проверка выхода группы за границы учитывают заголовок.
- Нельзя снова вычитать 30 из `e.h`, чтобы «освободить место под заголовок»: именно это раньше уменьшало портреты и смещало композицию.

В `heroLayout()`:

1. Фиксированный внутренний отступ HeroList — 4 с каждой стороны.
2. Базовая ячейка героя — **51 × 83**.
3. Подбираются число столбцов и единый scale, чтобы все ячейки помещались в доступные `w - 8`, `h - 8`.
4. Изображение имеет отступ 4 внутри ячейки, который **масштабируется вместе с ней**.
5. Портрет получается **43 × 75 × scale**, промежуток между изображениями — **8 × scale**.
6. Первое изображение начинается в `x + 4 + 4*scale`, `y + 20 + 4 + 4*scale`.

Точное отношение сторон изображения — **43 / 75**, а не старое приблизительное `0.575`. Промежуток не должен быть фиксированными 8 пикселями при любом размере. Заголовки не следует сжимать аргументом `maxWidth` у `fillText()`.

Портреты рисуются cover-crop без растяжения, с насыщенностью `0.7`, как в стилях игры. Нет подписей, уровней, бейджей или постоянной общей подложки группы. `GroupControl` использует тот же `heroLayout()` для позиции `+`.

Контрольный пример: первая группа `#grind mentality`, `w=488.695648`, `h=132.173920`, пять героев. На игровом скриншоте с масштабом около 115% портреты имеют примерно **74 × 129 px**, шаг между началами карточек — **88 px**. Это закреплено тестом.

### Масштаб и preview

`updateZoom()` подбирает fit по ширине и высоте; zoom ограничен 0.15–2.5. Backing buffer canvas пересчитывается под отображаемый zoom и device pixel ratio (DPR ограничен 2), а `paint()` задаёт transform по реальным размерам буфера. Только CSS-масштабирование старого буфера давало размытие текста.

Preview скрывает направляющие/выделение и использует тёмный тёплый градиент. Геометрия объектов и шрифты между preview и редактированием не меняются. Этот градиент — фон предпросмотра, не воспроизведение игрового 3D-фона.

## 10. История, жесты и сохранение

- `commit(mutate, message)` клонирует документ, применяет изменение, проверяет лимит, добавляет предыдущий документ в историю только при реальном изменении, сохраняет и перерисовывает. Ошибка откатывает документ.
- В приложении `new C.History(35)`: до 35 сохранённых прошлых состояний. История хранит сериализованные документы; это может быть затратно на больших рисунках.
- Один pointer-жест — одна запись истории. Во время движения документ/отрисовка обновляются, итог фиксируется при завершении.
- Escape/pointer cancellation отменяют текущий жест. Не сохраняй сотни исторических состояний на каждом `pointermove`.
- Resize вычисляется из исходной геометрии жеста. Shift можно нажать/отпустить в процессе; нельзя последовательно масштабировать уже изменённый результат.
- Snap применяется к дельтам до ограничения пропорций. Минимальный размер не даёт инвертировать прямоугольник.
- Новое изменение очищает redo. Undo/redo между сетками сбрасывает старый transient preview.

Autosave:

```text
dota-grid-studio.document.v1  → native-проект
dota-grid-studio.presets.v1   → пользовательские пресеты
```

Задержка autosave — 450 ms. Pending сохранение также сбрасывается на `pagehide` и при `dispose()`. При недоступном storage UI сообщает об этом и остаётся возможность скачать проект.

История, пиксели исходного изображения, временные selections/gestures и ручная замена шрифта не являются долговременными данными проекта. Применённые символы, слои и черновики сеток сохраняются.

`localStorage` привязан к origin: 4173 и 4174 имеют разные проекты. Между несколькими вкладками одного origin полноценного разрешения конфликтов нет; не открывай старую вкладку и не записывай её состояние поверх активного проекта пользователя.

## 11. Конвертация и генерируемые данные

В окне импорта доступны все параметры Line-Art Converter, кроме размера символов: яркость, контраст, инверсия, blur, резкость, порог, скелетизация, заполнение, шаг, плотность, лимит, обе строки символов, автоориентация, OnlyDots и параметры заливки. Настройки не скрыты в details. scripts/image-settings.mjs — общий источник значений по умолчанию и описаний полей для React и движка. По умолчанию лимит 1000; максимум 10 000 с общим бюджетом контура и заливки. Размер каждой экспортируемой категории остаётся 30×30.

Резкость 0–200% — unsharp mask после Gaussian Blur, перед Sobel; при 0 поведение прежнее. Ветка заливки берёт grayOrig (яркость исходных пикселей после композиции прозрачности на белый фон), учитывает инверсию и не зависит от brightness/contrast/sharpness контура. convertWithStats возвращает points и статистику фактического результата; convert остаётся совместимой обёрткой, возвращающей массив. Сохраняется детерминированный сэмплинг.

Кнопки «+» у imageCharset и imageShadeCharset появляются при наведении или фокусе, на touch всегда доступны. Они открывают общий modal поверх imageDialog: выбор категории из data/symbols.json и добавление отдельных символов к нужной строке. Изменения сразу пересчитывают черновой preview. Повторы в пользовательском charset допускаются (это порядок/вес выбора), каталог сам по себе не содержит дубликатов. OnlyDots отключает элемент autoOrient, сохраняя его значение для обратного включения. Ручное изменение параметра сбрасывает название выбранного пресета на «Свой стиль»; сохранение и импорт включают новые поля.

После выбора картинки открывается нативный модальный диалог imageDialog (разметка src/ImageImportDialog.jsx, стили styles/image-dialog.css). Предпросмотр рисуется на отдельном canvas imagePreview через тот же drawCategoryLabel; основной холст до применения не меняется. Настройки остались под управлением scripts/app.mjs. Кнопка «Добавить на холст» одной транзакцией C.addArtwork создаёт отдельный слой. Отмена, крестик, Escape и клик по фону очищают черновик без истории и автосохранения. clearImageDraft инвалидирует загрузку и отложенную конвертацию через imageRequest / convertRevision. Документные горячие клавиши заблокированы при открытом imageDialog; окно сохранения стиля открывается поверх него отдельным диалогом modal. После смены сетки или dispose незавершённая загрузка не должна открыть окно заново.

Источник библиотек символов — data/symbols.json: 442 уникальных символа в 14 категориях из списка пользователя от 26.09.2026. Генератор синхронизирует каталог сайта, обе автономные HTML-библиотеки и data/symbols.txt. Не редактируй эти копии вручную. Пресеты рамок в tools/pixel-ascii-editor.html используют только этот список. Пресеты изображений в presets/presets.json независимы от библиотеки: все 29 сохранены из исходного репозитория вместе с их charset, shadeCharset, autoOrient и onlyDots. Нельзя фильтровать их символы по каталогу или заменять линии точками. Ручной ввод, импортированные проекты и пользовательские пресеты также не фильтруются: нельзя удалять символы из существующей работы. tests/catalog.test.cjs проверяет совпадение библиотек, соответствие сгенерированных пресетов исходному JSON и использование собственных наборов символов каждым пресетом, включая линии, штриховку и японский стиль.

Проверка cmap радианс-шрифта показала отсутствие ┌─│╭█▓▒░. Браузер подставляет резервный шрифт, поэтому успешная отрисовка на сайте не доказывает совместимость с Dota. Список пользователя — ограничение библиотеки, не автоматическая проверка клиента игры.

`loadImage()` ограничивает изображение до 500 px по каждой стороне. `convert()` переводит его в яркость, композитит прозрачность на белый фон, применяет blur, Sobel, non-maximum suppression, hysteresis, thinning и пространственную выборку. Возможна штриховка/заливка символами; она детерминирована и использует общий бюджет с контурами.

- Конвертация выполняется на main thread с debounce 160 ms.
- Preview не меняет документ до применения.
- `imageRequest` / `convertRevision` защищают от устаревших результатов после смены картинки/сетки.
- Пустые и полностью прозрачные изображения должны давать пустой результат.
- Настройки ограничиваются по диапазонам; лимит результата конвертера — до 10 000 категорий, общий лимит документа — 10 000.
- Worker мог бы помочь на тяжёлых случаях, но пока не реализован.

Для регенерации:

```sh
node scripts/build-data.cjs
```

Генератор не обращается в сеть. Он читает data/symbols.json, исходные HTML-инструменты, снимок героев и пресеты; обновляет встроенные библиотеки символов в обоих HTML-инструментах. Расширение вертикального портрета определяется по существующему файлу. Сначала добавляй ресурс нового героя, затем пересобирай каталог.

Ручные изменения в `data.mjs` / `edges.mjs` могут исчезнуть при генерации. Править нужно источник или генератор. В генераторе сохранено исправление Canny для нулевого градиента; нельзя потерять его и получить заливку всего пустого изображения.

## 15. Как продолжать работу без регрессий

1. Прочитай задачу пользователя и проверь текущее дерево/ветку. Не заменяй приложение заново и не удаляй untracked-результаты предыдущей работы.
2. Найди владельца изменения: UI-компонент, движок, чистая модель, converter или общая игровая геометрия.
3. Для изменений документа используй транзакции/историю; временные preview и UI-фильтры не должны незаметно менять JSON.
4. Сохраняй совместимость native schema 1, все конфигурации, метаданные, скрытые слои и unknown hero IDs.
5. Геометрию портретов, выделения и `+` проверяй вместе. Отдельно помни про `e.h` против `visualHeight(e)`.
6. UI должен оставаться в высоте окна. Проверяй и короткое окно, и узкий экран; основная страница не должна превращаться в длинный лендинг.
7. Добавляй содержательные тесты для меняющейся логики, а не тесты, просто повторяющие реализацию. Для чисто текстовой документации запуск приложения не требуется.
8. После логических изменений выполни подходящие проверки и production build; после визуальных — также открой результат в браузере на изолированном origin.
9. Не заявляй о проверках в игре, touch, screen reader или физических клавишах, если их не выполнял.
10. Обновляй эту памятку, README/архитектуру/QA при изменении важных договорённостей. Источником истины при расхождении остаётся текущий код и воспроизводимая проверка.

Возможные направления дальнейшей работы (не обещанные и не реализованные автоматически): перенос инспектора в React, worker для конвертации, более компактная история больших документов, разрешение конфликтов нескольких вкладок, уточнение игровой отрисовки сложного текста, завершение релизных проверок и подготовка PR.

### Исправление белого экрана при обновлениях

`src/App.jsx` отделён от точки входа как Fast Refresh boundary. `src/main.jsx` сохраняет один React root в import.meta.hot.data. ### Редактор: совместимость и инструменты — 28 сентября 2026

- Координаты кисти и выделение используют общие helpers в scripts/canvas-input.mjs: центр видимого символа под курсором, привязка выключена по умолчанию, Shift меняет выделение, Alt+клик выбирает слой, двойной клик открывает текст. Поле текста многострочное с живым обновлением.

- Уменьшение плотности: отдельный предпросмотр до/после, удаление части одиночных символов без перемещения оставшихся, одно отменяемое действие. Текст и герои защищены. Объединение строк выполняется только при скачивании и теперь отключается галочкой.

### Плавный масштаб и оптимизация категорий — 28 сентября 2026

Масштаб холста теперь 1–800%: логарифмический ползунок, точный ввод дробного процента, плавное Ctrl+колесо с опорой под курсором. Размеры объектов и JSON не меняются. Новый оптимизатор сначала считает точное объединение строк без потерь. Опциональное сокращение деталей использует локальную плотность и направленность, сохраняет больше контуров и разреженных деталей; целевой бюджет учитывает строки как единицы экспорта. Превью до/после, применение с Ctrl+Z или скачивание результата без изменения холста. Отчёт и ограничения: docs/zoom-and-optimization.md. Проверки: 111 тестов, сборка и публичный браузер.
