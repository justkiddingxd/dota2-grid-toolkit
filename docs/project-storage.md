# Сохранение и восстановление проекта

`scripts/project-storage.mjs` отвечает за сохранность документа. `App.jsx` читает хранилище **до** открытия редактируемого холста; `app.mjs` передаёт изменения и показывает статус.

## Совместимость обновлений

- Неизменный ключ: `dota-grid-studio.document.v1`. Данные остаются native-проектом schema 1; старый ключ и импорт сохранены.
- IndexedDB: `gridstudio-projects`, store `documents`, версия базы 1. Версии приложения не должны переименовывать БД/ключ.
- Native JSON дополнен служебным `_studioSave` (ID записи, версия, время, авторская вкладка, родитель, признак конфликтующей копии). При загрузке в редактор поле удаляется из рабочего документа; на игровой Dota JSON оно не влияет.
- До миграции/первого сохранения в новой версии исходная строка сохраняется целиком, включая неизвестные поля. Если нет места для защитной копии, старое основное сохранение не перезаписывается.
- Если все копии не читаются, открывается пустое рабочее поле с явной ошибкой и защитой оригинала. Исходные данные доступны для скачивания; демопроект не записывается поверх них.

## Запись

Пауза после ввода 250 мс, максимальное ожидание при непрерывной работе 1 секунда. На visibilitychange, pagehide и размонтировании запись сбрасывается немедленно. Перед асинхронной транзакцией создаётся синхронный журнал отдельной вкладки в localStorage. При недостатке места/закрытии до завершения записи показывается стандартное предупреждение браузера о несохранённых изменениях.

IndexedDB хранит актуальную копию и до 10 автокопий по минутным слотам; копии перед обновлениями/восстановлениями не попадают под эту ротацию. localStorage хранит зеркало для совместимости и журнал последнего ввода. Если IndexedDB недоступна, localStorage сохраняет предыдущую хорошую запись перед заменой. Если localStorage заполнена, работа сохраняется в IndexedDB. При отказе обоих хранилищ статус не утверждает, что проект сохранён, и предлагает скачать файл.

Записи сериализованы. Web Locks координируют обычные записи между вкладками, а IndexedDB дополнительно сравнивает ожидаемую предыдущую запись в одной атомарной транзакции. Проверяется и актуальная строка localStorage. Вкладка с конфликтом не перезаписывает общий документ: сохраняет свою отдельную копию, сообщает об этом и позволяет восстановить её вручную. Незавершённый журнал восстанавливается автоматически только если он относится к актуальной ветке; чужая конфликтная копия не должна самовольно становиться основным проектом.

Меню «Копии проекта» открывается по статусу сохранения или из справки. Показывает время, имя, причину и версию, позволяет скачать исходный JSON, в том числе нераспознанный. Восстановление сначала архивирует текущий документ и актуальные сохранения других вкладок, затем заменяет рабочий документ одной отменяемой операцией.

## Что сохраняется

Весь native-документ: активная сетка, исходный файл со всеми сетками, отредактированные configDrafts, слои, скрытые объекты, координаты, герои, размеры холста, подложка. История Ctrl+Z существует в памяти сеанса, не восстанавливается после перезагрузки. Настройки/картинка ещё не подтверждённого окна конвертера и не добавленный на холст черновик рисования не являются частью native-документа.

Хранилище привязано к origin: https://gridstudio.me и его /editor используют один origin; www, HTTP, другой домен/порт — отдельное хранилище. Обновления должны сохранять HTTPS-домен и не отправлять Clear-Site-Data, не выполнять localStorage.clear/deleteDatabase и не принудительно перезагружать открытый редактор. Старый bundle должен продолжать работать до обычного обновления вкладки. При переходе на другой домен проект надо перенести скачанным файлом.

Ни код, ни сервер не могут восстановить данные после сознательной очистки браузера, потери профиля/диска или удаления данных в инкогнито. Для независимой копии — «Скачать текущий проект», не только Dota JSON. Никакой серверной передачи пользовательских сеток здесь нет.

## Проверки

`tests/project-storage.test.cjs` использует настоящую семантику IndexedDB-транзакций через fake-indexeddb. Проверяет старый файл, несколько сеток/подложку, резервирование до обновления, повреждённый JSON, восстановление журнала, quota/storage failures, одновременные записи, отдельную ветку второй вкладки, восстановление и ограничение автокопий. Проверять также reload + конфликт вкладок + восстановление через UI на локальном dev server. Production build для этой проверки не требуется.
