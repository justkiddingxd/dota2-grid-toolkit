# GridStudio 1.4.0: каталог, Telegram и рабочие пространства

Редактор получает отдельные файлы с резервными версиями и необязательной синхронизацией через Telegram. Пользователь может опубликовать одну сетку, пройти модерацию в Telegram и открыть её из каталога, сохранив остальные сетки своего файла.

- Каталог: поиск, теги, популярные по лайкам, личные публикации, обновления и жалобы; гости могут публиковать без аккаунта. ALTCHA и лимиты проверяются сервером.
- Необязательный вход через бота, профиль с аватаркой/@username, автоматическая привязка гостевых файлов и защита локальных правок при конфликте синхронизации.
- Резервные сохранения, восстановление, независимые рабочие пространства, предпросмотр всех сеток файла и возврат в редактор после reload.
- Перетаскивание героев, мишень ID 127, перенос за всю рамку выделения и Shift-сдвиг незавершённой фигуры. Плавный масштаб, оптимизация категорий и склейка строк только при экспорте.
- Focus, лендинг, обновлённый README и отдельная страница переезда для GitHub Pages. Все мелкие исправления перечислены одним пунктом в CHANGELOG.md.

Версия **1.4.0** следует согласованной ретроспективе 1.0–1.4, а не старому значению package.json. Схемы проектов, ключи браузера и данные прежних сеток сохраняются.

Проверки: 216 тестов и синтаксические проверки прошли; production build Vite собран. Интерфейс проверен локально на десктопе и мобильной ширине. Секреты, база, серверные настройки и пользовательские экспорты в PR не включены.

Для полного запуска нужны Node API + постоянная SQLite и отдельный Telegram worker; статика сама не запускает каталог и аккаунты. Инструкция — README и docs/catalog.md. GitHub Pages публикует страницу перехода по ручному workflow после принятия PR. Известная жалоба на положение символа под курсором без примера пользователя пока не воспроизведена.
